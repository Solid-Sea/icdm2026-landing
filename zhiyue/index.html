板端部署卡住的从来不是训练Edge deployment never fails at training

模型搬到板子上，卡点是那条又长又碎的迁移链：框架版本对不上、算子不支持、量化后精度掉了、NPU 跑起来反而更慢。很多项目停在「demo 在 PC 上通了」。 Moving a model onto a board fails along a long, brittle migration chain: framework versions disagree, operators are unsupported, quantisation costs accuracy, and the NPU sometimes runs slower than the CPU. Most projects stop at "the demo works on a PC".

真部署还要同时回答三个互相打架的问题：准确率够不够、延迟能不能接受、功耗撑不撑得住。 Real deployment must answer three competing questions at once: is accuracy enough, is latency acceptable, does power hold.

这是一台机器，不是一组脚本A machine, not a folder of scripts

六个能力全部在板端完成，不依赖网络：人脸识别（YuNet 检测 + ArcFace 特征）、表情分类、植物图像匹配（MobileCLIP）、OCR、语音识别（Paraformer）、语音合成（Sherpa）。 All six functions run on the board with no network dependency: face recognition (YuNet detection plus ArcFace features), expression classification, plant-image matching (MobileCLIP), OCR, ASR (Paraformer) and TTS (Sherpa).

一条迁移链，一个运行时One migration chain, one runtime

  • PC → ONNX → RKNN：固定链路，每一步产物可复现，不靠逐模型手调。 PC → ONNX → RKNN: a fixed chain with reproducible artifacts at each step, not hand-tuned per model.
  • CPU 默认、NPU 备选：不是「能上 NPU 就上」，每条路线都用实测量化收益之后才决定。 CPU default, NPU optional: not "NPU wherever possible" but "NPU only where the measured gain holds".
  • ModelRuntime 统一后端：六个能力共用一套调用接口，换后端不改业务代码。 ModelRuntime as one backend: six functions share a single call interface; swapping backends leaves application code untouched.

同一模型，三个数字一起变好One model, three numbers moving the right way

配对评测：同一个 MobileNetV2 三分类模型，分别在 CPU 默认路线和非量化 NPU 路线上跑。 Paired evaluation: the same 3-class MobileNetV2 model run on the CPU default route and on the unquantised NPU route.

延迟降到 1/4.6、功耗降约 36%，准确率还高了 2.8 个百分点——因为这条 NPU 路线不靠量化换速度。这是本页最值得看的一组数：通常「快」和「准」要二选一，这里没有。 Latency drops 4.6×, power falls about 36%, and accuracy is 2.8 points higher — because this NPU route does not buy speed with quantisation. It is the number worth reading twice: usually speed and accuracy trade against each other, and here they do not.

功耗为直供电流快照，不是积分能耗。 Power figures are direct-DC current snapshots, not integrated energy.

其余板端测量Other on-board measurements

  • 植物匹配：MobileCLIP 315 ms；120 张授权图像上精确物种 81.7%、下游任务 89.2%。 Plant matching: MobileCLIP at 315 ms; 81.7% exact-species and 89.2% downstream accuracy on 120 licensed images.
  • 语音合成：Sherpa 合成至 WAV 4909 ms（含写盘）。 TTS: Sherpa synthesis to WAV at 4909 ms, including file write.
  • 人脸特征：ArcFace 特征占用降至约 1/4。 Face features: ArcFace footprint reduced to roughly one quarter.

能用在哪儿Where it earns its place

博物馆与展厅Museums and exhibitions

网络不可靠、设备要连轴转一整天、识别与讲解要即时响应。Unreliable networks, all-day operation, instant recognition and narration.

教室与研学Classrooms and field study

多台设备同时离线运行，功耗与成本都可控。Many units offline at once, with bounded power and cost.

隐私敏感现场Privacy-sensitive sites

人脸与画面只在本地处理，一步都不出设备。Faces and frames processed locally; nothing leaves the device.
